# SHAPE 엔티티 테스트 시나리오

대상: `ShapeEntityParser` (`parser.ts`), `parseEntities` 디스패치, `DxfParser.parseSync`.
구현: `parser.test.ts`(기본 3건), `parser.adversarial.test.ts`(아래 ID 와 1:1), 실도면은 `scripts/verify-shape.ts`.

DXF 레퍼런스 그룹코드: 100(AcDbShape), 39 두께, 10/20/30 삽입점, 40 크기, 2 모양 이름, 50 회전(기본 0), 41 X 배율(기본 1), 51 기울기(기본 0), 210/220/230 돌출 방향(기본 0,0,1) + 공통 엔티티 코드(5, 330, 8, 6, 62, 370, 48, 60, 67, 410, 102 그룹, XDATA 1001~).

## 발견 사항 요약
- SHAPE 전용 파서 버그는 발견되지 않았다.
- O-02 / S-04: 중복·미지 그룹코드에서 엔티티 파싱이 중단되어 뒤 필드가 사라진다. `createParser` 공통 동작이라 SHAPE 만 고치지 않고 현재 동작으로 문서화.
- O-05: (해결, #189) 좌표 그룹에서 20 이 빠지면 y=0 으로 복구한다.
- D-05: AcDbEntity 마커가 없으면 subclassMarker 가 비어 있다(R12 스타일 파일). 공통 스니펫 순서 문제로 문서화.

## C. 완전성 보강 (2차 검토)

DXF 레퍼런스(SHAPE: 100, 39, 10/20/30, 40, 2, 50, 41, 51, 210/220/230)와 공통 엔티티 코드를 파서 코드와 맞춰 보고, 빠진 시나리오와 약한 단언(toBeDefined 만 확인하던 것)을 보강했다.

| ID | 입력 | 기대 결과 |
|---|---|---|
| C-01 | 공통 코드 6/62/420/440/370/48/67/410 | 각 필드 값이 정확히 매핑 |
| C-02 | 코드 60 = 1 / 0 | isVisible = true / false (현재 동작, 아래 발견 사항) |
| C-03 | XDATA 1001/1000/1040 | `xdata` 가 `[{appName, value:['hello', 3.5]}]` 와 정확히 같음 (S-07 보강) |
| C-04 | 102 리액터·확장딕셔너리 | `extensions` 구조 정확히 비교 (S-08 보강) |
| C-05 | shapeName `__proto__`/`constructor`/`prototype` | 문자열 그대로 저장, 프로토타입 오염 없음 |
| C-06 | 210/220/230 비정규 값 | 축별로 정확히 매핑 |
| C-07 | 39/41/51 개별 지정 | 기본값을 덮어씀, 나머지 기본값 유지 |
| C-08 | 빈 SHAPE 두 개 연속 | ensureHandle 이 숫자 handle 을 연속으로 부여 (D-04 단언 강화) |

### 2차 발견 사항 (공통 동작, 코드 미수정)

- 코드 60 은 DXF 에서 0=보임, 1=안 보임인데 공통 스니펫이 `ToBoolean` 으로 `isVisible` 에 넣어 의미가 반대가 된다. 모든 엔티티 공개 API 에 걸린 동작이라 고치면 호환이 깨지므로 테스트로 현재 동작만 고정했다.
- handle 이 없는 엔티티는 `ensureHandle` 이 숫자 handle 을 넣어 문자열 handle 과 타입이 섞인다.
